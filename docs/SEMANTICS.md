# 语义字典（机制与模板）

> **本文件只定义机制与模板，不含任何真实业务口径。**
> 真实台账落在**被评审项目根目录的 `SEMANTICS.md`**，内容随项目而变，**必须从该项目代码/配置中取证**，禁止把示例当事实。
> 校验责任：`docs/roles/code-reviewer.md` 的 **R8**（一号一义 / 一义一号）。

## 一、两个文件的分工

| 文件 | 位置 | 内容 | 维护者 |
|---|---|---|---|
| 机制（本文件） | 本工作流仓库 `docs/SEMANTICS.md` | 规则、表结构、评审动作、初始化方法 | 工作流维护者 |
| **台账** | **被评审项目根 `SEMANTICS.md`** | 该项目真实的「取值 ↔ 含义 ↔ 上下文」映射 | 该项目每轮 `/code-review` 追加 |

**收录范围**：枚举值、状态码、错误码、类型标识位；租户 / 业务线 / 渠道标识；金额单位与精度口径（分/元、scale、`RoundingMode`）；配置 key（ducc / properties）、消息 topic 与队列名、缓存 key 前缀；库表字段的取值域与含义。

项目若已有等价的既有载体（枚举类、常量类、数据字典表、接口文档），**以项目既有载体为准**，台账只做索引与补充，不得另立一套说法。

## 二、首次评审的初始化（项目没有台账时）

1. **从既有代码/配置反推**候选口径：枚举类、常量类、`@Value` 与 ducc key、DB 字典表、对外报文与 DTO 定义
2. **只登记已被引用的取值**：不从设计稿、不从命名猜测
3. **每条必须带来源**：`文件:行`、配置 key、或库表字段名，便于复核
4. **登记结果须用户确认才生效**：评审员**不得自行断言**项目既有口径是什么
5. 初始化完成前，R8 只报「未登记/无法取证」，不得直接判冲突

## 三、登记规则

1. **先登记，后使用**：未登记的取值不得硬编码；必须由枚举或常量类收口，禁止散落魔法值
2. **一号一义**：同一取值不得在不同上下文表示不同含义 → 违反即 **blocker**
3. **一义一号**：同一含义不得在不同模块用不同取值 → 违反即 **major**
4. **变更即改登记**：含义或取值变更须走 `/change`，同步更新台账；删除取值须标注下线版本
5. 模块内专属取值可登记到项目内 `rules/<module>.md`，全局冲突仍以项目台账为准
6. 不做"占位预留"：未使用的取值不登记，避免台账变成猜测清单

## 五、评审动作（R8 三步）

1. **抽取值面**：从 `git diff` 抽出新增/修改的常量、枚举项、状态码、错误码、标识位、配置 key、topic、缓存 key 前缀
2. **取证对账**：对每个取值到「项目台账 → 项目既有代码/配置」两级取证，判定：
   - 同字段不同义 → **blocker**（附既有取值来源位置）
   - 同义不同值 → **major**
   - 无来源可取证 → 先按「未登记」处理（major），不得凭空判冲突
3. **回写**：本轮新增取值登记进项目台账，并在 `06a-code-review.md` 记「新增语义 N 条 / 未取证 M 条」

## 六、冲突处理

- 不得就地覆盖旧含义；须由用户裁决：改新代码取值，还是走 `/change` 迁移旧口径
- 迁移期间旧值保留须标注下线版本，否则按 R6（无用代码）一并清理

## 七、虚构示例（仅用于理解规则，**禁止写入任何台账**）

> 以下取值与业务线纯属虚构，只为说明判据形态。

- 假设某项目台账已登记：`tenantId = 1` → 业务线 A（来源：该项目的租户枚举类）
- 若新需求把 `tenantId = 1` 定义为业务线 B → 触发**一号一义**，判 blocker，必须另分配取值
- 若新需求把业务线 A 在另一模块写成 `"A-LINE"` 而旧代码用 `1` → 触发**一义一号**，判 major
- 真实取值、真实业务线，一律以**被评审项目台账与代码**为准，本文件不提供任何默认值
